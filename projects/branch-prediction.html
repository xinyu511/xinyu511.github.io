Branch prediction in gem5

We implemented predictors in gem5 on an in-order ARM core with a 64 kB L1 and 1 MB L2, and simulated 8 million instructions of four SPEC CPU 2017 benchmarks. I wrote the TAGE predictor, the perceptron predictor, and our custom hybrid TAGE+ predictor.

The hybrid TAGE+ predictor is best or tied on every benchmark. The gains depend on the program: branch-heavy code with local patterns (nab_r, imagick_r) gains 26–38%, while deepsjeng_r barely moves with any predictor.

Out-of-order structures in SystemVerilog

The second lab moved to the structures that make out-of-order execution correct: a register renaming unit that maps architectural registers to physical ones and tracks free registers, a reorder buffer that retires instructions in program order, and an issue queue that wakes up instructions when their operands are ready. I built the renaming logic. We synthesized the components in Cadence Genus and studied core configurations in gem5's out-of-order model.
