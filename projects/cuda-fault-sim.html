A CUDA differentiable fault simulator

Automatic test pattern generation can be posed as gradient descent over a probabilistic circuit simulator. That only pays off if the simulator is fast. We moved it onto the GPU.

The problem

A differentiable fault simulator computes, for every gate, the probability of each logic value and of a stuck-at fault being observable, so test patterns can be optimized by gradient descent. The baseline was written in Python on a graph library (DGL).

What we built

  • Custom CUDA kernels for logic-value propagation and fault-observability propagation, called from PyTorch through a C++ extension so gradients still flow.
  • A layer-by-layer schedule: one kernel launch per topological level, one thread per gate, so every gate's inputs are ready when it runs.
  • A flat circuit layout: gates as arrays with fan-ins in CSR form, a switch over 16 gate types, and input patterns processed in batches.
  • A dead end, measured: a dependency-table version that dropped the level ordering was 38% slower, limited by memory bandwidth, and we abandoned it.

Results

All four circuits peak between 128 and 256 threads per block. Kernel time is lowest at 128 threads (25 µs, against 52 µs at 32 threads) and 11% slower at 512. Speedup grows almost linearly with batch size up to 32 and peaks at batch 64, where the kernels use 338 of the GPU's 360 GB/s of memory bandwidth, so the simulator ends up bandwidth-bound rather than compute-bound.
